# Immich Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show Immich albums in LightCraft as Local-style views over a mounted Immich storage, and ask Immich to rescan after imports/exports write into it.

**Architecture:** A native-only engine module `immich` (config, path map, small JSON client over `lightcraft-fetch`) feeds a new `LibrarySource::Immich` view whose filter is "these photo ids, under this folder" (Local photos only show in folder-scoped views). Imports (`commit_prepared`) and exports (`AfterExport`) hand written paths to a debounced background rescan. The UI adds an "Immich" left-panel section and loads albums on a worker thread with the same `ImportJob::prepare` / `commit_prepared` split the Local browse uses.

**Tech Stack:** Rust, `lightcraft-fetch` (http/https, rustls), `serde_json`, egui.

**Spec:** `docs/superpowers/specs/2026-11-16-immich-design.md`

## Global Constraints

- Native only: every new engine item is `#[cfg(not(target_arch = "wasm32"))]` (the web build has no `lightcraft-fetch`).
- Never crash: no `unwrap`/`expect`/`panic!`/indexing on response data in non-test code; JSON from the server is hostile; response bodies capped at **16 MiB**; requests use `connect: 5 s`, `stall: 30 s`.
- No API key, server address or personal path in the repo, catalog or `prefs.json`. Config lives only in `$XDG_CONFIG_HOME/lightcraft/immich.json` (fallback `~/.config/lightcraft/immich.json`); `IMMICH_API_KEY` overrides `api_key_file`.
- Missing config file = feature off (commands return an error naming the file; UI hides the section).
- New code in new files; edits to upstream files are hooks of a few lines.
- Long-running work holds a `TaskGuard` from `session.activity.start(...)`.
- Paged search: `POST /api/search/metadata` body `{"albumIds":[id],"type":"IMAGE","size":1000,"page":N,"withExif":false}`; `assets.items[].originalPath`, `assets.nextPage` (string or null). Albums: `GET /api/albums` → `[{id, albumName, assetCount}]`. Libraries: `GET /api/libraries` → `[{id, importPaths:[..]}]`. Scan: `POST /api/libraries/{id}/scan` (204). Auth header `x-api-key`.
- Parity checklist / gaps docs are **not** updated (fork-only feature; would conflict on every upstream rebase).
- Gate per task: `cargo clippy -p <crate> --all-targets -- -D warnings` and the task's tests; `cargo xtask ci --quick` before the final commit.

## Review Focus

- **Server down / mount offline** while clicking an album → an error toast/status ("Immich unreachable: …" / "N photos not on the mount"), the app keeps working. Test: Task 3 `browse_album_counts_missing_files`, Task 2 `client_reports_connection_refused`.
- **Album with photos from an unmapped path** (e.g. a library added later) → those are counted as `unmapped`, the rest show. Test: Task 3 `browse_album_counts_unmapped`.
- **Path-prefix confusion** (`/mnt/media/Lib` vs `/mnt/media/Library`) → only whole-component prefixes match. Test: Task 2 `map_path_matches_whole_components_only`.
- **Local browsing must never trigger rescans** (every folder click would ping the server). Test: Task 4 `local_browse_sends_no_rescan`.
- **Malformed / oversized JSON** → error, no panic. Test: Task 2 `parse_rejects_malformed_and_wrong_shapes`, `client_caps_body_size`.

### Task 4: Rescan after imports and exports

**Files:**
- Modify: `crates/engine/src/immich.rs` (rescan), `crates/engine/src/import/commit.rs` (before `Ok(report)` ~l.337), `crates/engine/src/export/prepare.rs` (`AfterExport` field + `after_export` + `run`/`start`)
- Test: `crates/engine/src/tests/immich.rs`

**Interfaces:**
- Produces: `pub struct Rescans` (Clone; `Session.immich_rescans: Rescans`), `impl Rescans { pub fn request(&self, cfg: &Config, paths: Vec<String>, activity: &crate::activity::Activity); pub fn wait_idle(&self) /* tests and one-shot CLI */ }`.
  - Behaviour: paths not mapped by `to_server` are dropped; if none remain, nothing. Otherwise add to a pending set; if no worker is running, spawn one that waits **3 s** (coalescing batches), takes the pending set, `libraries()`, and `scan()`s each library whose any `import_paths` entry is a whole-component prefix of a pending server path; repeat while pending is non-empty. Errors → `log::warn!` and an activity row failure; never propagate. Holds a `TaskGuard` labelled "Telling Immich about new files" with `Cancel::No`.
  - Delay is a field (`Rescans::with_delay(Duration)`) so tests use 0.
  - Import hook: `if !opts.local && !report.imported.is_empty()` → paths of the imported photos → `s.immich_rescans.request(...)` when `s.immich` is set.
  - Export hook: `AfterExport { immich: Option<(Config, Rescans, Activity)> }` filled by `after_export` when `s.immich` is set; `run`/`start` call `request` with the files' `"path"` values (both paths) and leave the Apple Photos outcome unchanged.
